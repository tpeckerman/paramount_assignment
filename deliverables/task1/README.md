# Task 1 deliverables

Everything the brief asks for, and nothing else. Generated by `pipeline/build_deliverables.py` from the repository root, which holds these files alongside the apparatus that produced them.

| Asked for | Where |
|---|---|
| Sources and a table of rules | `1_sources/`, `2_rules/` |
| The full prompt | `3_prompt/`, run in that order |
| The test cases | `4_test_cases/` |
| The results of the runs | `5_results/` |
| A short explanation of design choices | `6_design_choices/TASK1_WRITEUP.md` |
| The models and tools used | same file, last section |

## What each file is for

| File | Why it is here |
|---|---|
| `1_sources/00_SOURCE_INVENTORY.md` | deliverable 1: the sources, with links and scope |
| `1_sources/originals` | the documents themselves, so every quote can be checked |
| `2_rules/RULES_TABLE_v1.xlsx` | deliverable 1: the table of rules |
| `2_rules/Rules.csv` | the same rules as plain text |
| `3_prompt/RUN_1_describe_content.md` | deliverable 2: reads the content |
| `3_prompt/RUN_2_decide.md` | deliverable 2: applies the rules and decides |
| `4_test_cases/CASES.md` | deliverable 3: the test cases |
| `4_test_cases/inputs` | each case's input on its own, as fed to the prompt |
| `5_results/RESULTS.md` | deliverable 4: the results |
| `5_results/runs` | the raw model outputs, so the results can be checked rather than believed |
| `5_results/PROMPT_DEFECTS.md` | what running the prompts exposed, which the improvement in the write-up refers to |
| `6_design_choices/TASK1_WRITEUP.md` | deliverables 5 and 6: design choices, and the models and tools used |
| `6_design_choices/SCOPE.md` | where the boundary sits, which deliverable 1 asks for as scope of applicability |
| `7_extra/timeline.html` | not asked for: a 24-hour view of which rules bite when, built from the table |

## What is deliberately not here

The prompt that built the rules table, and the sixteen scripts that fetch, check and render. The brief asks for a table of rules, not for a method of producing one. Those live in the repository and are described in its README.

## Read this first

`5_results/RESULTS.md` is the honest one. All eight cases were run blind, by agents that had not seen the expected answers, and the raw outputs are in `5_results/runs/` so the claims can be checked rather than believed. It also records what the runs got wrong, including a prediction of mine that turned out to be false.
